### 软件对照组

| 类型 | 实现原理 |
|---|---|
| 自动化脚本-代码开发 | 通过安卓无障碍服务注入"逻辑手势事件" |
| 自动化脚本-屏幕录制 | 录制真人操作后回放，同样走无障碍注入 |

**为什么硬件比软件难查？**

软件走安卓无障碍服务注入，而无障碍是否开启、设备是否 root、是否运行在虚拟机里，App 都查得到——**硬件规避的是这一类"环境检测"**。上表 8 台里有 4 台（HID 蓝牙、OTG、鼠标点击器、自动滑屏+点击器）走 HID 协议，在系统看来就是一个外接鼠标，属于原生支持的设备类型，没什么可查的。

需要说明的是，**"产生真实触摸"并不是采购动机**——这 4 台 HID 设备的接触面积恒为 0，同样没有真实触摸，却是其中最便宜、最普及的一类。物理触头产生的真实接触面积，是电容点击器、机械臂这类设备为完成任务顺带带来的副产品。

而恰恰是这个副产品，构成了检测的第一层分水岭：**环境检测和行为检测是两件事。** HID 设备躲得过"这台手机有没有被改过"，躲不过"这一下到底有没有碰到屏幕"——接触面积恒为 0 或恒为占位值 1，是系统对非触摸输入源的必然上报，物理上无法伪造。

## 测试场景

覆盖 5 种手机状态——这一步是为了让传感器维度（线性加速度、陀螺仪）有对照基线，也是为了验证"真人在不同姿势下是否仍可区分"：

| 场景 | 说明 |
|---|---|
| 室内 - 平放手机 | 手机放桌面，力被桌面吸收 |
| 室内 - 竖放手机 | 手机立在支架上，更容易被触碰带动 |
| 室内 - 手持手机 - 坐着 | 最接近日常使用 |
| 室内 - 手持手机 - 行走 | 引入身体晃动 |
| 地铁 - 手持手机 - 坐着 | 引入外部环境振动 |

## 测试项

| 动作 | 变体 |
|---|---|
| 点击 | 固定位置 / 随机位置 / 固定位置带坐标偏移 |
| 滑动 | 固定位置向上滑 / 随机位置向上滑；真人另分拇指、食指 |
| 组合 | 向上滑动 + 点赞 + 收藏（模拟真实刷短视频行为链） |

设计这些变体是为了拿到"点击空间分布"这一维：固定点高度重复、局部矩形抖动、大范围随机，三种模式在真人和工具之间的分布完全不同。

## 样本量

分两轮：

| | 每项次数 | 目的 |
|---|---|---|
| 第一轮 | 20–50 次 | 探索哪些维度有区分力 |
| 第二轮 | **300–500 次** | 扩大样本、验证第一轮结论、固化阈值 |

第二轮中有 4 个维度的结论与第一轮**不一致**（路径冗余率、平均曲率、速度波动、部分传感器场景），说明小样本下的结论并不稳定——这也是引擎默认设置最低样本量门槛（SWIPE ≥30、TAP ≥50）的直接原因。

## 数据采集

自建 Android 采集 App（`gesture-collector-v2.apk`，在 [Releases](../../../releases) 页面提供），每次手势记录一行汇总数据，同时以十几毫秒的间隔记录逐点轨迹。

### 手势级汇总 CSV

```
gesture_index, method, target_element, gesture_type,
start_x, start_y, end_x, end_y, timestamp_ms, duration_ms,
avg_pressure, max_pressure, touch_major, touch_minor, avg_size,
max_speed_x, max_speed_y, max_speed, total_distance, max_acceleration, avg_curvature,
accel_x/y/z, gyro_x/y/z, gravity_x/y/z, linear_x/y/z, mag_x/y/z,
pointer_count, trajectory_points
```

### 轨迹点 CSV

```
gesture_index, point_index, x, y, pressure,
touch_major, touch_minor, vx_px_s, vy_px_s, curvature
```

**轨迹点 CSV 是必需的**：压力波动、接触面积、速度波动、路径冗余率四个维度全部依赖逐点数据，只给汇总 CSV 会损失大部分判别力。

### 派生特征的计算口径

| 特征 | 计算方式 |
|---|---|
| 接触面积 | `π/4 × touch_major × touch_minor`，逐点求后取均值 |
| 压力波动系数 | 单次手势内 `pressure` 的标准差 / 均值 |
| 速度波动系数 | 单次手势内瞬时速度的标准差 / 均值（只统计速度 > 0 的点） |
| 路径冗余率 | `实际路径长度 / 起终点直线距离 − 1`（见下方注意） |
| 线性加速度合量 | `√(linear_x² + linear_y² + linear_z²)` |
| 陀螺仪合量 | `√(gyro_x² + gyro_y² + gyro_z²)` |

> ⚠️ **路径冗余率的两种口径**
> 分析文档里的"冗余率 = 1"指的是 `路径长度 / 直线距离 = 1`，即完全无冗余。
> 代码里的 `path_redundancy_rate` 是**这个比值减 1**，无冗余时为 0。
> 例如"真人比直线多走 4.8%"，文档口径是 1.048，代码口径是 0.048。
> `config/default_rules.json` 中的阈值全部采用**代码口径**。
