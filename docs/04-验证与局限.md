# 04 · 验证与局限

**中文** · [English](./en/04-validation-and-limits.md)

## 盲测

用 5 种特征典型的方式各采一批全新数据（不参与规则制定），喂给引擎做盲判：

| 实际设备 | 引擎判定分布 | 判对 / 总数 |
|---|---|---:|
| 真人 - 食指向上滑动 | 真人 50 | 50 / 50 |
| 自动化脚本 - 屏幕录制 | 屏幕录制 50 | 50 / 50 |
| 真人 - 拇指向上滑动 | 真人 53 / 未知 1 | 53 / 54 |
| 鼠标点击器 | 鼠标点击器 39 / HID 11 | 39 / 50 |
| 机械臂 | 机械臂 48 / 未知 18 | 48 / 66 |

> ⚠️ **这不是准确率指标。** 每组只有几十条样本，即使全对，
> 置信区间下限也只在 93% 左右；换设备批次、换机型，结果都会变。
> 这组数字用来定位**错误发生在哪里**，不构成任何性能承诺。

**没有出现跨大类的错误**——真人从未被判成机器，机器也从未被判成真人。所有错误都发生在同一大类内部（软件类内混淆）或退化成"未知"。这是这套方法目前最值得信赖的一点。

## 误判归因

### 鼠标点击器 22% 误判为 HID

拆开这 50 条看，判对和判错的两组几乎无法区分：

| | 接触面积 | 平均压力 | 平均速度 | 速度波动 |
|---|---:|---:|---:|---:|
| 判对的 39 条 | 0 | **0.9444** | 546 | 0.326 |
| 判错的 11 条 | 0 | **0.9524** | 541 | 0.397 |

差别只在压力，而 `pressure_one_min = 0.95` 这条分界线**正好压在这批数据的众数上**。压到 0.9524 的落进"压力恒为 1"的软件 / HID 分支，压到 0.9444 的没落进去。

更值得注意的是：**规则里"鼠标点击器压力常见 0.5"这一条，在这批验证数据上一次都没触发过**——实测压力是 0.94。78% 的正确率完全靠"无接触 + 速度 <800 px/s"这一条规则撑着。这说明压力 0.5 的结论**与设备批次或 ROM 相关，不能当作稳定特征**。

### 机械臂 27% 输出未知

机械臂的各项特征都落在真人和脚本之间，而识别它的规则是多个条件的 AND 组合，取值区间偏窄。这 18 条样本在大部分维度上都符合机械臂特征，只有一维落在了区间之外，整条规则就没有命中。

真人那 1 条未知同理——接触面积和压力都略低于真人区间的下沿。

这暴露的是**分层设计上的不足**：目前的规则直接从"有没有真实接触"这个粗分类跳到了具体设备型号，中间缺一层过渡。理想情况下，特征明确属于物理接触类、但不匹配任何已知型号的手势，应该归到"物理接触类 / 型号未知"，而不是和完全没有特征的样本一起落进"未知"。

### 改进方向

具体的改进项以 [Issues](../../../issues) 跟踪，欢迎带着你自己采集的数据来提 issue 或 PR。尤其欢迎两类贡献：

- **新设备样本**（标签 `new-device`）——这个项目的价值取决于覆盖了多少种真实工具
- **机型标定数据**（标签 `calibration`）——当前阈值只在我们的实验设备上验证过

## 局限

### 1. 不是实时拦截器

SWIPE 需 ≥30 条、TAP 需 ≥50 条才输出正式结论。做的是**账号 / 会话级定性**，拦不住单次请求。合适的位置是跟在现有拦截链路后面做定性和溯源，不是替代它。

### 2. 需要端侧埋点

压力、接触面积、逐点轨迹只有 App 内能采到。网关侧、CDN 日志、服务端接口日志里没有任何一个必需字段。

### 3. 阈值需按机型标定

`contact_area > 15000`、`speed > 4000 px/s` 都是绝对值，与屏幕 DPI、触控驱动、ROM 强相关。当前阈值基于我们的实验设备，**换机型必须重新校准**。

上面鼠标点击器压力 0.5 与 0.94 的矛盾，就是这个问题最直接的例子。

### 4. 传感器两维需要上下文

线性加速度 / 陀螺仪的判定规则依赖 `phone_status`（手持 / 平放 / 行走）标注。生产环境的埋点通常没有这个字段，此时这两维不参与判定，实际可用的是 7 维。

另外，行走和地铁场景会同时污染这两个维度（见 [02 · 九维度分析](./02-九维度分析.md)），此时应主动降权。

### 5. 规则引擎，不是训练出来的模型

优点是每条判定可解释、可审计、可以直接拿去出报告；缺点是阈值需要随设备和采集环境校准，不会自己适应新设备。

### 6. 置信度不是概率

输出的 `confidence` 是得分的单调变换，不是统计意义上的后验概率，**不能当作"有 99% 的把握"来解读**。它只适合做同一批数据内部的排序，不适合跨批次比较。
