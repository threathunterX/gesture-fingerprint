# 实验数据与方法论

这里是 [gesture-behavior-classifier](../README.md) 全部判定规则背后的实验依据。

我们采购了 8 类市售作弊硬件、自建 2 类软件脚本对照组，在多种手机状态下让真人和每一类工具做同样的操作，累计采集数万条手势，从 9 个维度逐项比对，最后把结论固化成可运行的规则引擎。

## 一页速查

**像人程度的稳定排序：**

```
代码脚本  <  鼠标点击器  <  电容点击器  <  机械臂  <  真人
 最假                                      最像人
```

**九维度区分力：**

| 维度 | 区分力 | 一句话 |
|---|---|---|
| 滑动速度波动系数 | 很高 | 脚本接近 0，真人约 0.51，刷屏器一最高约 1.09 |
| 按压接触面积 | 很高 | 软件注入 / HID / 鼠标为 0，真人最大 |
| 按压力度 | 高 | 脚本 / HID 恒为 1.0，真人分布最分散 |
| 压力波动系数 | 高 | 脚本几乎为 0，真人 P50 ≈ 0.23 |
| 滑动平均速度 | 中高 | 自动滑屏点赞器最快，鼠标点击器最慢 |
| 滑动路径冗余率 | 中 | 真人 P95 明显长于机械臂，绕路更多 |
| 滑动平均曲率 | 中 | 脚本接近 0，机械臂波动最大 |
| 线性加速度合量 | 中 | 反映手机是否被真实手持移动 |
| 陀螺仪合量 | 中 | 同上，且对"竖放手机"场景区分力意外地强 |

## 关于"9 个维度"

这个数字容易数不清，这里说明一次：

| | 数量 | 说明 |
|---|---|---|
| 分析结论的维度 | **9** | 上表那 9 个，是实验分析的口径 |
| 引擎实际读取的特征 | **10** | 上述 9 个，**外加"点击空间分布"**（固定点重复 / 局部偏移 / 全屏随机）。它是批次级特征，只对 TAP 生效，所以没有被算进"9 维"里 |
| 线上通常实际生效的 | **7** | 线性加速度、陀螺仪两维需要「手机状态」（手持 / 平放 / 行走）标注才参与判定，生产埋点一般没有这个字段。让引擎自行推断手机状态是 [Issue #4](../../../issues/4) |

另外有一项分析结论**没有进入代码**：第 4 维"滑动平均速度曲线"分析出了真人的"加速—峰值—减速"三阶段形态，但引擎目前只使用了速度的**标量均值**，没有实现曲线形状匹配。这是这一维当前被打折使用的部分，跟踪在 [Issue #5](../../../issues/5)。

**最重要的一条结论：**

> 段位最高的机械臂能在**单个维度**上骗过判定——速度曲线有加速—峰值—减速，轨迹曲率甚至和真人一样高。
> 但它躲不过 9 个维度交叉：压力波动太小、抖动太规律、手机晃动又不够，总有一项对不上。
>
> **单一特征，再高级的工具都能模仿；多维组合，才能锁死高段位工具。**
